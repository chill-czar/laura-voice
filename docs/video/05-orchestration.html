Orchestration

The layer that actually distinguishes a demo from a product. Everything here is my code.

Why the LLM is not the orchestrator

An LLM is a probabilistic function. Given the same input it may produce different output, and it has no enforceable notion of "not allowed". A business process needs the opposite: the same input must produce the same decision, and illegal transitions must be impossible rather than unlikely.

So I split them. The model proposes; deterministic code disposes.

USER SPEECH

    ▼
  probabilistic            LLM  ──── proposes: "call proceed_to_qualification"

    ▼
  deterministic   CallOrchestrator.prepareHandoff()

  validated       ToolRegistry.wrap()  ── zod-validate input
    │
    ▼
  typed           CaseService / AppointmentService
    │
    ▼
  durable         PostgreSQL

The state machine

GREETING→ TRIAGE→ INTAKE→ QUALIFICATION→ SCHEDULING→ CONFIRMATION→ COMPLETED
↑ QUALIFICATION → INTAKE loops back when the result is INSUFFICIENT ↑
HANDOFF_HUMAN ERROR_RECOVERY — reachable from most states, terminal or recoverable 
export const PHASE_TRANSITIONS: Record<CallPhase, CallPhase[]> = {
  GREETING:      [TRIAGE, ERROR_RECOVERY],
  TRIAGE:        [INTAKE, HANDOFF_HUMAN, COMPLETED, ERROR_RECOVERY],
  INTAKE:        [QUALIFICATION, HANDOFF_HUMAN, COMPLETED, ERROR_RECOVERY],
  QUALIFICATION: [SCHEDULING, INTAKE, HANDOFF_HUMAN, COMPLETED, ERROR_RECOVERY],
  SCHEDULING:    [CONFIRMATION, INTAKE, HANDOFF_HUMAN, ERROR_RECOVERY],
  CONFIRMATION:  [COMPLETED, ERROR_RECOVERY],
  COMPLETED:     [],   // terminal
  HANDOFF_HUMAN: [],   // terminal
  ERROR_RECOVERY:[TRIAGE, INTAKE, COMPLETED],
};

Who owns what

Agent (LLM policy)

  • Conversational phrasing
  • Which tool seems relevant
  • Extracting meaning from messy speech
  • Deciding a question is answered

Orchestrator

  • Current phase + legal transitions
  • Which agent is active
  • What context is assembled
  • Qualification outcome
  • Call lifecycle / teardown

Tool + services

  • Input validation (zod)
  • The actual mutation
  • Idempotency
  • Error containment
  • Emitting tool events

Handoff — the actual code path

// TriageAgent — the LLM can only ever *ask*
tool({
  name: "begin_intake",
  execute: async () => {
    const result = orchestrator.prepareHandoff(AgentName.INTAKE);
    if (!result) return "I'm not able to move to intake right now.";  // refused
    return handoff({ agent: result.agent, returns: "Continuing to intake." });
  },
})

// CallOrchestrator — the only place a transition actually happens
prepareHandoff(target: AgentName) {
  const targetPhase = PHASE_FOR_AGENT[target];
  const changed = this.transitionPhase(targetPhase, `handoff to ${target}`);
  if (!changed && this.state.currentPhase !== targetPhase) return null;  // ← the gate
  this.state.activeAgent = target;
  void this.eventService.emit(AGENT_HANDOFF, {...});
  return { agent: AGENT_FACTORIES[target](this), phaseChanged: changed };
}

Qualification — deterministic on purpose

export function evaluateQualification(input): QualificationResult {
  const hasInjury     = (input.injuries?.length ?? 0) > 0;
  const supportedType = SUPPORTED_INCIDENT_TYPES.includes(input.incidentType);
  const dateKnown     = Boolean(input.incidentDate);

  if (input.representedByAttorney === true)
    return { status: DISQUALIFIED, reasons: ["already_represented_by_attorney"] };

  if (hasInjury && supportedType && dateKnown)
    return { status: QUALIFIED, reasons: [] };

  return { status: INSUFFICIENT, reasons };  // machine-readable why
}
packages/shared/src/intake.ts — a pure function, zero LLM calls
This is the line I'd defend hardest. A law firm cannot have a language model deciding who is disqualified — that has to be a rule someone can read, version, and audit. The model's job is to figure out whether the caller said they have an attorney. The rule's job is to decide what that means. QualificationAgent only explains the outcome; it has no tool that can change it.
