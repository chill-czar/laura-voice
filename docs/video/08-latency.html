To add before recording (30 minutes of work, big payoff)

// In entry.ts — stamp when the user's final transcript lands,
// then emit one aggregate event when first audio goes out.
let turnStartedAt: number | null = null;

session.on(UserInputTranscribed, (ev) => {
  if (ev.isFinal) turnStartedAt = Date.now();
});

// inside the tts_metrics branch of MetricsCollected:
if (turnStartedAt) {
  void orchestrator.eventService.emit("latency.turn_total", {
    durationMs: Date.now() - turnStartedAt,
    metadata: { ttftMs: lastTtft, ttsTtfbMs: Math.round(m.ttfbMs) },
  });
  turnStartedAt = null;
}

That single event turns the Latency panel from a list of stage timings into the number that actually matters — and it's the number Biswa will ask about.

Why streaming is non-negotiable

Without streaming

  • Wait for the entire utterance → transcribe
  • Wait for the entire LLM response
  • Wait for the entire audio file
  • Then start playing

Latency = sum of all four completions. A 4-second answer takes 4 seconds before a single word is heard.

With streaming (this system)

  • STT emits partials continuously, final on endpoint
  • LLM streams tokens — TTS starts on the first sentence
  • Audio frames pushed to the room as they arrive

Latency = time to the first unit at each stage. Response length stops mattering for perceived responsiveness.

The extraction one is my favourite because it's a real bug I introduced and then fixed. I had it awaited inline, which meant every single turn paid for two sequential LLM calls before the agent could speak. Moving it to a tracked background promise — with qualification awaiting that exact promise before it reads the fields — kept correctness while removing a whole round-trip from the critical path.

Not yet done — name these if asked

  • Semantic turn detection. LiveKit ships a turn-detector model that predicts end-of-turn from transcript content; I'm on plain VAD endpointing. That ~578ms is the most compressible number on the page.
  • Speculative/preemptive generation. Start the LLM on a partial transcript and discard if the user continues.
  • Prompt caching. The policy blocks are stable across turns and are re-sent every time.
  • Model tiering. Triage could run on a much smaller model than intake.
  • p50/p95 aggregation. Today I can read one call's timeline; I can't yet alert on a regression.
