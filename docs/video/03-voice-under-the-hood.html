What each stage actually does

VAD — Voice Activity Detection

A small binary classifier over short audio windows: is this frame speech or not? Silero is a compact ONNX model running locally in the agent process — no network hop inside the turn loop.

  • Does not know words, meaning, or who is speaking
  • Cheap enough to run continuously on every frame
  • Its output is the trigger for "user started/stopped talking"

entry.ts → silero.VAD.load(), prewarmed once per worker

Endpointing — the harder problem

VAD says "silence right now". Endpointing decides "the turn is over". A pause mid-sentence is not the end of a turn. Get this wrong in either direction and the call feels broken:

  • Too eager → you interrupt the caller mid-thought
  • Too patient → dead air, feels laggy

Measured in this project as latency.end_of_utterance (~580ms observed).

Honest note: this uses standard VAD-based endpointing. LiveKit also ships a semantic turn-detector model that predicts end-of-turn from transcript content — I did not enable it. That's a real, nameable next step.

STT — streaming speech recognition

Audio frames go up a websocket continuously; the model returns partial hypotheses that get revised, then a final when it commits.

  • Partials let the UI feel live and let the system react early
  • Finals are what the orchestrator actually acts on
  • Streaming is the whole point — batch STT would add the entire utterance duration to latency

Observed: one spoken thought often arrives as 4–6 separate finals

TTS — streaming synthesis

Text is chunked by a sentence tokenizer and streamed to Deepgram over a websocket; audio frames come back and are pushed into the LiveKit track as they arrive.

  • We never wait for the full response before speaking
  • Time-to-first-byte is what the caller perceives (~300ms observed)
  • Audio already sent to the room cannot be un-played — only future audio can be cancelled

What the LLM receives — and what it does not control

The LLM decides

  • What sentence to say next
  • Which allowed tool is relevant
  • What arguments to pass
  • Whether the caller's meaning is clear
  • Which facts appear in free text

The orchestrator decides

  • Which phase the call is in — isTransitionAllowed()
  • Whether a handoff is legal — prepareHandoff()
  • Whether the caller qualifies — evaluateQualification()
  • Which tools even exist for this agent
  • What context the model is allowed to see
  • What actually gets written to Postgres
The model never receives the transcript and returns a database write. It returns a proposal. Deterministic code decides whether that proposal is allowed, and only typed services touch the database.

What is lost when audio becomes text

This is the honest cost of a cascaded architecture, and it's worth naming precisely.

SignalSurvives STT?Consequence here
Words / semantic contentYesThis is what the whole pipeline is built on
Rough timing / pausesPartlyAvailable as timestamps, not as meaning
Prosody, intonationNo"Fine." (angry) and "Fine!" (relieved) become identical text
Emotion / distressNoReal gap for an injury intake line — a distressed caller reads as neutral
Speaker identity / overlapNoNo diarization configured; two people on speakerphone merge
Background acousticsNoCan't tell "roadside, just crashed" from "quiet office"
I chose to accept this loss. In exchange I get an exact transcript I can log, replay, diff, evaluate and show a compliance reviewer — which for a legal intake product is worth more than prosody. That's a tradeoff I made deliberately, not a limitation I didn't notice.

Two different meanings of "architecture"

Application architecture — what I built

Transport, turn-taking, orchestration, state machine, context assembly, tools, persistence, observability. This is the layer a forward-deployed engineer actually owns and changes per customer.

Model architecture — what I use

Encoders, transformer stacks, vocoders, training objectives. I understand the public concepts and can reason about the tradeoffs, but I did not train or modify any of these models — and I won't imply otherwise.

Do not blur these two on camera. Claiming model-internal knowledge you don't have is the fastest way to lose credibility with someone who does have it.
