Observability side-channel

Every orchestration step also emits a CallEvent → Postgres (durable audit) + Redis pub/sub → apps/api SSE → React timeline. The frontend never polls, and never touches Postgres or Redis directly.

Concept vs implementation

ConceptImplementationWhy this one
Voice gatewayLiveKit CloudOwns WebRTC/SFU, jitter buffer, track lifecycle — not worth rebuilding
Turn detectionSilero VADLocal ONNX, no network hop in the turn loop
Speech recognitionDeepgram nova-3True streaming with partials; non-streaming would add whole-utterance latency
LLM gatewayOpenRouterModel swappable by env var; no provider lock-in in code
Speech synthesisDeepgram auraSame vendor/key as STT; streaming first-byte ~300ms
OrchestrationCallOrchestratorBusiness control flow must be deterministic, not model-decided
Context engineeringContextServiceOne place decides what the model sees — auditable
Tool executionToolRegistry + servicesSingle validation/logging boundary for every state mutation
Durable statePostgreSQL + PrismaBusiness records must survive process death
Ephemeral state / eventsRedisLosing Redis loses the live feed, never the matter
PresentationNext.js + SSEThin layer; renders from the event log only
